# Hyuyangnim 설계서 — 자연휴양림 예약 오픈 조회

> 2026-08-03 브레인스토밍 확정본. 근거·실측 출처는 `CLAUDE.md`, 결정 경위는 `BRAINSTORM.md`.

## 1. 무엇을 만드나

**즐겨찾기한 자연휴양림의 다음 예약 오픈일을, 열면 바로 보여주는 모바일 웹 한 장.**

실사용자는 **부모님 두 분**(아이폰 1 · 안드로이드 1). 공개 서비스가 아니고 로그인도 없다.
이 제약이 설계의 거의 모든 것을 정한다 — 큰 글씨, 화면 2개, 설정 화면 0개, 타이핑 0회.

### 하지 않는 것 (경계선)

- **예약 자동화(매크로) 금지.** 언제 열리는지 보여줄 뿐, 대신 예약하지 않는다.
  로그인·결제·좌석선점 자동화는 설계에 넣지 않는다.
- **로그인 벽 뒤 크롤링 금지.** 숲나들e 추첨 페이지가 여기 해당한다(§2 실측).
- **푸시 알림 없음.** 2026-08-03 사용자 결정으로 제외 (§3.1).
- 수집은 공개된 일정·정책·공지에 한정. 실시간 예약현황 폴링은 대상 아님.
- 사이트 부하 금지 — 정책 확인은 주 1회로 충분.

## 2. 실측으로 확정된 사실 (2026-08-03, Edge+CDP)

### 2.1 규칙은 휴양림마다 형태 자체가 다르다

| 휴양림 | `hmpgId` | 선착순 오픈 규칙 (공식 원문) | 형태 |
|---|---|---|---|
| 축령산 (경기 남양주) | `ID02030050` | **매월 7일 09:00** 부터, 다음달 말일까지 | 월 단위 |
| 영인산 (충남 아산) | `ID02030012` | **매주 수요일 09:00** 부터, 6주차 화요일까지 | 주 단위 |

⚠️ **블로그발 "축령산 6일"은 오보였다. 공식은 7일.**
⚠️ 둘 다 지자체 운영인데 반복 주기의 **종류**가 다르다. 운영주체로도 안 묶인다.
→ **"국립은 수요일, 공립은 매월 1일" 같은 일반화를 코드에 넣지 말 것.** 규칙은 휴양림별 데이터다.

### 2.2 추첨 일정은 크롤링으로 얻을 수 없다

- 사이드 메뉴의 정책 페이지는 `ruleId` **101(선착순) · 105(지역주민우선) · 107(바우처우선) · 112(관광취약계층우선)** 뿐 —
  **추첨 정책 페이지가 존재하지 않는다.**
- `/rep/drlts/month/drltsMain.do` (월추첨신청)는 **로그인 벽** 뒤다.
- → 추첨 규칙은 선착순 정책 원문의 언급("월추첨 발표 후")과 공지사항을 **사람이 읽고 손으로 등록**한다.

### 2.3 딥링크는 `hmpgId`만 바꾸면 전 휴양림에 통용된다

| 용도 | 경로 |
|---|---|
| 선착순 예약 | `/rep/or/sssn/fcfsRsrvtPssblGoodsDetls.do?hmpgId=<ID>&menuId=001001` |
| 월추첨 신청 | `/rep/drlts/month/drltsMain.do?hmpgId=<ID>&menuId=001003002` |
| 예약정책 | `/pot/rm/ug/selectRsrvtGdncView.do?hmpgId=<ID>&menuId=004001001&ruleId=101` |

⚠️ 월별현황조회는 `movePageUsingNetFunnel(...)` JS 경유(대기열 시스템) → **딥링크 불가**.
오픈 시각에 대기열이 걸리는 것은 정상이며 우회하지 않는다.

### 2.4 정책 페이지는 순수 텍스트 문단이다

표(`<table>`)가 없고 본문이 평문 문단이라 **본문 텍스트 해시 비교만으로 변경 감지가 된다.**
단 헤더·푸터·슬라이드 텍스트가 섞이므로 본문 영역만 잘라내야 한다(영인산 페이지에 슬라이드 문구가 섞여 나왔다).

## 3. 확정된 설계 결정

### 3.1 알림 없음 — 열면 보이는 페이지 (2026-08-03 사용자 결정)

브레인스토밍 중반까지 웹푸시(PWA)로 결정돼 있었으나, 사용자가 **"알림을 따로 만들지 말고 웹페이지에
접속하면 볼 수 있게"** 로 방향을 바꿨다. 이에 따라 서비스워커·푸시 구독·발송 크론·VAPID·`.ics`
내보내기를 **전부 제거**한다.

⚠️ **감수하는 대가:** 부모님이 스스로 열어보셔야 오픈일을 아신다. 선착순은 그날 아침에 안 여시면
놓치신다. → **"열기 쉬움"이 유일한 안전장치**가 되므로 `manifest.json`(홈 화면 아이콘)만은 남겨
한 번 탭으로 열리게 한다.

⚠️ **화면에 뜬 날짜가 유일한 정보원이 됐다.** 틀린 날짜를 보여주면 부모님이 그걸 믿고 헛걸음하신다
→ §3.4의 자동 중단 규칙이 알림이 있을 때보다 **더** 중요해졌다.

### 3.2 커버리지 — 목록은 전국, 규칙은 확인된 것만

**목록과 규칙은 비용이 완전히 다르다.** 목록(이름·주소·도/시군)은 공공데이터포털
전국휴양림표준데이터(`15013111`)로 거의 공짜, 규칙은 정책 페이지를 하나씩 사람이 읽어야 한다
(4곳 30분 / 170곳 며칠).

→ **전국 목록을 다 보여주되, 규칙 없는 곳은 `오픈일 확인 중` + 예약 사이트 링크만.**
- 시/군까지 드릴다운하면 목록이 짧으니 그 안에서 확인된 곳을 위에 배치
- 부모님이 미확인 휴양림을 고르시는 것 자체가 "이거 채워라"는 신호가 된다
- 규칙을 채우면 즉시 자동 반영된다 (부모님이 다시 뭘 할 필요 없음)

⚠️ **규칙은 사람이 확인한 것만 쓴다 — 자동 파싱한 규칙을 화면에 띄우지 말 것.**
정책 원문은 자연어라 파싱이 가능은 하지만, 틀린 날짜를 부모님이 믿고 준비하셨다가 놓치신다.
**틀린 날짜 한 번이 앱 신뢰를 통째로 무너뜨린다 — 없느니만 못하다.**
→ 크롤링의 역할은 "규칙 자동 생성"이 아니라 **"정책 원문을 모아 검토하기 쉽게 놓아주기"**.

### 3.3 즐겨찾기는 공유 저장소에 둔다

두 분이 각자 폰으로 보시므로 `localStorage`는 따로 논다(어머니가 추가한 게 아버지 폰에 안 보임).
→ Supabase에 단일 공유 목록. 계정·로그인 없음.

### 3.4 정책이 바뀌면 즉시 멈춘다

정책 페이지 본문이 바뀐 것이 감지되면:
1. 그 휴양림을 **즉시 `오픈일 확인 중`으로 되돌리고**(`rules.active = false`) 날짜 표시를 멈춘다
2. 스크립트가 변경 사실과 원문 diff를 출력 → 관리자가 검토해 규칙을 고치면 자동 재개
3. 부모님 화면에는 '확인 중'만 보인다 — 별도 경고 문구를 띄우지 않는다

⚠️ **옛 규칙으로 날짜를 계속 보여주는 것이 가장 나쁜 실패 모습이다.** 되돌리지 말 것.
대가: 관리자가 방치하면 그동안 그 휴양림 날짜가 안 뜬다. 대신 상태가 정직하다.

## 4. 아키텍처

### 4.1 산출물

```
index.html      앱 전체 (홈 · 추가) — CSS/JS 인라인
manifest.json   홈 화면 아이콘 (PWA 최소 구성)
check.js        주 1회 정책 감시 스크립트 (로컬 실행, 배포물 아님)
```

`Our_Budget`의 구조(단일 HTML + Supabase + Cloudflare Workers, `git push` → 자동 배포)를 따른다.
단일 HTML이 2파일이 된 이유는 홈 화면 아이콘용 `manifest.json`뿐이다.

⚠️ **`worker.js`를 미리 만들지 말 것.** `Our_Budget`은 리포에 Worker 코드가 없고
(추적 파일이 `index.html`·`CLAUDE.md`·`backup_appscript.gs`·`.gitignore` 4개뿐)
Cloudflare 대시보드의 GitHub 연동이 정적 파일을 그대로 서빙한다. 같은 방식이면 Worker 코드가
아예 필요 없다 — 배포를 먼저 붙여보고 정말 필요할 때만 추가한다.

**서버 로직은 0이다.** 다음 오픈일 계산은 전부 브라우저에서 돈다.

### 4.2 데이터 모델 (Supabase)

```sql
create table forests (
  id        serial primary key,
  name      text not null,              -- 축령산자연휴양림
  sido      text not null,              -- 경기
  sigungu   text not null,              -- 남양주시
  hmpg_id   text unique,                -- 숲나들e ID. null이면 숲나들e 미등록
  addr      text,
  tel       text
);

create table rules (
  id             serial primary key,
  forest_id      int  not null references forests(id) on delete cascade,
  kind           text not null check (kind in ('fcfs','lottery')),   -- 선착순 / 추첨
  freq           text not null check (freq in ('monthly','weekly')),
  day_of_month   int  check (day_of_month between 1 and 31),   -- monthly. 축령산 = 7
  weekday        int  check (weekday between 0 and 6),         -- weekly. 0=일, 영인산 = 3(수)
  open_time      time not null default '09:00',
  apply_end_day  int,        -- 추첨 전용: 신청 마감일
  result_day     int,        -- 추첨 전용: 발표일
  note           text,       -- 부모님께 그대로 보여드릴 한 줄
  source_url     text not null,   -- 조례로 바뀌므로 출처 필수
  verified_at    date not null,   -- 사람이 확인한 날
  active         bool not null default true,
  check ( (freq='monthly' and day_of_month is not null)
       or (freq='weekly'  and weekday      is not null) )
);

create table favorites (
  forest_id  int primary key references forests(id) on delete cascade,
  added_at   timestamptz default now()
);

create table policy_snapshots (
  forest_id   int primary key references forests(id) on delete cascade,
  url         text not null,
  body_hash   text not null,
  body_text   text,                                   -- diff 확인용 원문 보관
  checked_at  timestamptz not null default now()
);
```

RLS는 모든 테이블 `for all using (true) with check (true)` — `Our_Budget`과 동일.
개인정보가 없고(즐겨찾기 목록이 전부), 로그인을 두지 않기로 한 결정의 귀결이다.

**검증:** 축령산 = `monthly / day_of_month=7 / 09:00`, 영인산 = `weekly / weekday=3 / 09:00`.
실측한 두 형태가 모두 들어간다.

**의도적으로 넣지 않은 컬럼:** 휴관일, 예약 대기 규칙, 감면 혜택, 최대 숙박일수.
정책 페이지에 있지만 **"언제 열리나"에 답하지 않는다.** 화면에 늘면 답이 묻힌다.

`rules`는 관리자가 Supabase 대시보드에서 손으로 채우는 표다. 앱에 관리 화면을 만들지 않는다.

### 4.3 다음 오픈일 계산 (브라우저 JS)

```
monthly : 이번 달 min(day_of_month, 그 달 말일) 의 open_time
          → 이미 지났으면 다음 달로
weekly  : 오늘부터 가장 가까운 weekday 의 open_time
          → 오늘이 그 요일인데 open_time 이 지났으면 +7일
lottery : day_of_month = 신청 시작일. apply_end_day 까지 신청, result_day 에 발표
          정렬·D-day 기준은 신청 시작일
```

⚠️ **말일 클램프 필수.** `매월 31일` 규칙이 2월을 만나면 그 달 말일로 당긴다.
안 하면 그 달 표시가 조용히 사라진다.

시간대는 부모님 폰의 로컬 시간(KST)을 그대로 쓴다 — 서버 크론이 없어져 UTC 변환이 사라졌다.

## 5. 화면

**두 개뿐. 설정 화면은 만들지 않는다.** (알림 타이밍 같은 고를 것이 없어졌다)

### 5.1 홈 — 열자마자 이것

```
┌────────────────────────────────┐
│  다음 예약 오픈                 │
├────────────────────────────────┤
│  축령산자연휴양림               │
│  8월 7일 (금) 오전 9시          │  ← 22px 굵게
│  4일 뒤 · 선착순                │
│  ┌──────────────┐  ┌─────────┐ │
│  │ 예약하러 가기 │  │ 빼기    │ │
│  └──────────────┘  └─────────┘ │
├────────────────────────────────┤
│  강씨봉자연휴양림               │
│  오픈일 확인 중                 │  ← 회색
│  ┌──────────────┐              │
│  │ 예약 사이트   │              │
│  └──────────────┘              │
├────────────────────────────────┤
│      ＋ 휴양림 추가하기          │
└────────────────────────────────┘
```

- **가까운 오픈일 순 정렬.** '확인 중'은 맨 아래
- 본문 18px 이상, 날짜 줄 22px 굵게, 터치 타깃 최소 48px, 고대비 (노안 전제)
- 날짜 표기는 `D-3`이 아니라 **"4일 뒤"**, 당일이면 **"오늘 오전 9시!"**
- `예약하러 가기` = §2.3 딥링크 (`kind`에 따라 선착순/추첨 경로)
- `빼기` = **즉시 삭제 + 8초 되돌리기 토스트.** 확인창 없음
  - 오터치 방지는 확인창이 아니라 **시각 위계**로: 주 버튼은 크고 진한 색, `빼기`는 회색 아웃라인
  - ⚠️ 확인창을 겹겹이 두지 말 것 — 그것도 부모님께 부담이다
- 앱을 열 때마다 Supabase에서 자동 로드. 당겨서 새로고침 같은 제스처는 두지 않는다

### 5.2 추가 — 3단 드릴다운, 타이핑 0회

```
  ← 뒤로   어디에 있나요?          ← 뒤로   경기도 어디?
 ┌───────┐┌───────┐              ┌───────┐┌───────┐
 │ 경기  ││ 강원  │               │ 남양주││ 가평  │
 └───────┘└───────┘              └───────┘└───────┘
 ┌───────┐┌───────┐              ┌───────┐┌───────┐
 │ 충남  ││ 충북  │               │ 안성  ││ 포천  │
 └───────┘└───────┘              └───────┘└───────┘
```

- 도 → 시/군 → 휴양림. 같은 화면 안에서 단계만 바뀐다(화면 수를 늘리지 않음)
- 휴양림이 있는 도/시군만 버튼으로 노출
- 3단에서 **규칙이 확인된 곳을 위에**, `확인 중`은 회색으로 아래에
- 이미 즐겨찾기한 곳은 ✓ 표시, 누르면 해제
- ⚠️ **검색창을 넣지 않는다.** 오타·한글 IME 때문에 부모님께 최악의 입력 수단이고,
  시/군까지 들어가면 목록이 몇 개뿐이라 있으나 마나다

### 5.3 문구 규칙

- 전문용어 금지. `선착순`·`추첨`은 부모님이 아는 말이므로 사용 가능
- `hmpgId`, `크롤링`, `동기화` 같은 말은 화면에 등장하지 않는다

## 6. 정책 감시 스크립트 (`check.js`)

로컬 Node 스크립트. Windows 작업 스케줄러로 **주 1회** 실행.

```
즐겨찾기 + 규칙 등록된 휴양림의 정책 URL
  → Edge + CDP 로 렌더 (§7 참조)
  → 본문 영역만 추출 → 공백 정규화 → SHA-256
  → policy_snapshots 의 body_hash 와 비교
  → 다르면  rules.active = false  +  콘솔에 diff 출력  +  스냅샷 갱신
```

⚠️ **Cloudflare Worker cron을 쓰지 않는 이유:** Worker에는 브라우저가 없어 순수 `fetch`만 가능한데,
그것만으로 이 페이지 본문이 나오는지 검증되지 않았다. 알림을 없앤 뒤로 크론을 쓸 다른 이유도 사라졌으므로,
**이미 동작을 확인한 Edge+CDP 방식**을 그대로 쓰는 편이 확실하다.
